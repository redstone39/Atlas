# Community and feedback

Atlas welcomes use, evaluation, feedback, and discussion. The public repository
is maintained separately from private development and is not currently open to
external code contributions.

## What is welcome

- reproducible bug reports;
- documentation corrections and clarity feedback;
- self-hosting and deployment experiences;
- environment, Provider, LDAP, and Active Directory compatibility reports;
- questions, use cases, architecture discussion, and feature ideas.

## Where to participate

Use [GitHub Issues](https://github.com/redstone39/Atlas/issues) for a
specific reproducible defect, documentation problem, or deployment and
compatibility report. Use the repository's Issue form that best matches the
observed problem.

Use [GitHub Discussions](https://github.com/redstone39/Atlas/discussions)
for questions, self-hosting experiences, architecture discussion, broader use
cases, and feature ideas that are not yet a bounded defect.

For an actionable report, include only what is safe to publish:

- the affected commit and component;
- the environment and supported path exercised;
- the minimum reproduction steps;
- expected and observed behavior;
- sanitized logs or screenshots when they materially help.

Never publish credentials, private documents, Provider payloads, access tokens,
database dumps, internal endpoints, or unredacted logs.

## Pull request boundary

This repository does **not** accept external pull requests or unsolicited
patches at this time. There is no announced timeline for changing this
boundary. Opening an Issue or Discussion does not create an implementation or
support commitment.

You may use, modify, and distribute the Apache-2.0-licensed source in your own
fork. Maintainers may discuss an idea or investigate a report without accepting
an upstream patch.

## Security reports

Do not open a public Issue or Discussion for a vulnerability. Follow the
private-reporting process in [`SECURITY.md`](SECURITY.md).

## Response expectations

Atlas is a technical-evaluation project. Reports and discussions are welcome,
but no response time, support SLA, implementation schedule, compatibility
commitment, or production support is offered.
